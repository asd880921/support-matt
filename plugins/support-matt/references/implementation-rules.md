# 實作規範

`implement-stepwise` 與 `implement-oneshot` 共用。修改本檔會同時影響兩者。

## TDD

調用 Matt 的 **`/tdd`** skill，取得測試品質判準：好測試的定義、seam 概念、以及三個 anti-pattern（implementation-coupled、tautological、horizontal slicing）與 `tests.md`、`mocking.md` 的具體規則。這些內容不在此重複，一律以 `/tdd` 為準。

在其之上套用三條覆寫：

**覆寫 1 — seam 只確認一次。** `/tdd` 要求「寫任何測試前先寫下 seam 並與使用者確認，未確認的 seam 不得寫測試」。照字面執行會在每個 commit 前多一道詢問，與逐 commit 的節奏疊在一起造成雙重關卡。改為在流程的規劃／開場階段一次列出全部 seam 並取得確認，之後不再逐一重問。**調用端 skill 負責指定該確認發生在哪一步**；未經確認的 seam 仍然不得寫測試。

**覆寫 2 — 先看它失敗，且必須因為對的理由失敗。** `/tdd` 只說 "Red before green"。本規範要求：執行測試，確認它**因「功能尚未實作」而失敗**，而非因語法錯誤或環境問題而失敗。**此步驟不得跳過**——沒看過它失敗，就不知道它測的是不是對的東西。

**覆寫 3 — 重構就地處理，不推給 review 階段。** `/tdd` 寫著「Refactoring is not part of the loop. It belongs to the review stage (see the `code-review` skill)」。但本套流程的 `code-review` 是選用的、可能不執行，照抄會讓重構無處可去。改為：在**剛寫出的程式碼**內、且測試保持綠燈時做最小整理。

- **不得改動本次以外的既有程式碼**（不順手重構、不改周邊命名、不調整格式或註解）。
- **預設不整理**，可直接省略此步。
- 若判斷需要較大範圍的重構，**不要就地進行**，依「暫停與回報」提出，由使用者決定。

### 例外

純設定檔、無邏輯的樣板或產生碼、純文件、一次性拋棄式變更，可不適用測試先行，但**須在回報中說明原因**。

## 程式碼與註解

- **預設向既有程式碼看齊。** 動手前先看同目錄的既有檔案，沿用現行分層、命名慣例、錯誤處理方式與格式風格，不引入新風格、新抽象或新依賴。個人偏好一律讓位給專案現況。
  - 可偏離的情況僅限：既有寫法有明確缺陷（安全性、正確性、資源未釋放）、使用已棄用 API、既有風格本身不一致無單一慣例可循，或 ticket 已明訂不同做法。
  - **偏離時必須在回報中指出**「哪裡沒有沿用、依據哪一條理由、影響範圍」，讓使用者可當場否決。不得靜默偏離。
- **代碼層不寫需求文件編號**（`FR-xx`、`BR-xx`、`AC-xx`、`DC-xx` 等）。改為直接描述行為本身。ticket 與規格文件仍正常使用這些編號。
- **註解收斂到最少。** 只保留程式本身無法表達的約束或非顯而易見的推論，一個約束一行。刪除敘述性、提醒性、解釋本次改動理由的註解——那些屬於 commit message。測試斷言預設不加註解。

## Commit

使用 conventional commit 格式。

- 允許的 type 僅 `feat`、`fix`、`refactor`、`chore`、`test`。
- Commit type prefix 保持英文，描述以繁體中文撰寫。
- 若本次工作有已知的來源 issue 編號（例如經 `gitlab-issue-fetch` 取得的 GitLab issue），每則 commit message 都必須包含 `#<issue_number>`；純本地 ticket 無此編號時省略。
- 測試與其對應的實作屬於**同一個 commit**，不另拆。

## 邊做邊記

每完成一個 commit，記錄本次寫出的測試以及它們涵蓋的 ticket 驗收條件編號。

- 只記**本次實際寫出**的測試，不要把既有測試算進來。
- 測試名稱寫到可直接搜尋的程度（檔名 + 測試方法名）。
- 沒有對應到任何驗收條件時（例如純重構、設定檔），寫「無」，不要硬湊。
- 驗收條件編號以該 ticket 內的出現順序為準。

**這份記錄是線索，不是證明。** 它由實作者自己填寫，等同自我聲明；真正的驗證由 `to-acceptance-map` 在開發完畢後於獨立 session 執行。因此不需要為了「好看」而美化——沒寫測試就照實留空，那正是驗證階段要抓的東西。

**記錄位置由調用端 skill 指定。**
